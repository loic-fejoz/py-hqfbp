# Testing Guidelines

Interoperability and bit-accuracy are the primary goals of the `py-hqfbp` test suite.

## 1. Unit Tests
Location: `tests/`.
Uses `pytest`. Covers core codec logic, header merging, and generator/deframer state machines.
```bash
pytest
```

## 2. Simulation (Performance Verification)
Location: [src/hqfbp/simulate.py](file:///home/loic/projets/py-hqfbp/src/hqfbp/simulate.py).
Used to stress-test the heuristics of the `Deframer` under simulated bit errors.
```bash
# Example simulation run
python -m hqfbp.simulate --ber 1e-3 --count 100 --encodings "gzip,h,rs(120,100)"
```

## 3. Cross-Implementation Compatibility
**This is the most critical part of testing for the reference implementation.**
Scripts in the parent directory (`test_cross_compat_*.sh`) verify that PDUs generated by Python can be decoded by Rust and vice-versa.

- **KISS Roundtrip:** Use `src/hqfbp/pack.py` and `src/hqfbp/unpack.py` to generate `.kiss` files and verify reassembly.
- **Reference Check:** If you change any logic, you MUST run the Rust implementation against your output to confirm you haven't broken the protocol spec.

## Best Practices
- **Reference Objects:** Use the objects in `tests/conftest.py` if available for consistent test data.
- **CBOR Inspection:** Use `cbor2` directly in tests to verify that headers contain the exact keys required by the [RFC](https://github.com/loic-fejoz/hqfbp/blob/main/rfc.md).
- **RNG Seeding:** Always seed random bit flippers in tests to ensure reproducible failures.

> [!IMPORTANT]
> **Verification Mandates:**
> - **Always verify `pytest` before committing.** As the reference implementation, any regression in Python will propagate to all other language ports.
> - **Zero Regression Rule:** EVERY bug fix MUST be accompanied by a new unit test in `tests/`.
